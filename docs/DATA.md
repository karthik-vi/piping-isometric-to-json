**This is not client data.** No drawing from any employer or client was used, copied, or traced.
The layout (title block, BOM, isometric route) follows generic piping-drafting conventions.

## Why synthetic

I did not find a public, licensed piping-isometric dataset with field-level labels (web search, 2026-11-03).
Closest public resources found, none of which fit:
- Title-block detection on *building* drawings: Lombardi et al., arXiv 2504.08645 (https://arxiv.org/abs/2504.08645).
- A P&ID drawing collection on Zenodo (https://zenodo.org/records/8028570): P&IDs are schematics, not isometrics.
- OCR for mechanical drawings, Frontiers in Manufacturing Technology 2023 (https://frontiersin.org/articles/10.3389/fmtec.2023.1154132/pdf): code, not a labelled set.
Real isometrics are almost always project-confidential.
Decision recorded in `DECISIONS.md` (ADR-001).

## Regenerate

```bash
python scripts/generate_dataset.py --out data/synthetic/dev  --n 30 --seed 1
python scripts/generate_dataset.py --out data/synthetic/test --n 60 --seed 2
```
Generation is deterministic for a given seed (checked by `tests/test_pipeline.py::test_generator_is_deterministic`).

## What a drawing contains (= label schema, `schemas/isometric.schema.json`)

- Title block: drawing no, line no (`<NPS>-<service>-<seq>-<spec>`), size, spec, material, design pressure (barg), design temp (°C), revision.
- BOM table: 4–7 rows of item / qty / unit / description.
- Drawing area: isometric route of 4–8 segments on the 6 isometric directions; per-segment dimension text in mm,
  written **parallel to the pipe** (so at ±30° or ±90°); 2–5 valve symbols with horizontal instrument/valve tags on leaders;
  the line number written along the first segment.
- `service` is not printed in the title block; ground truth derives it from the line number.

## Degradation ("scanned" split)

Rotation U(−1.2°, 1.2°), Gaussian blur r∈U(0.6, 1.1), Gaussian noise σ∈U(8, 18), 0.2% black speckle, contrast/brightness jitter.

## Limitations (read before trusting any number)

- One font family (DejaVu Sans), one sheet template, one fixed vocabulary (6 specs, 6 services, 8 tag prefixes, 8 BOM stems).
  The rule stage uses that same vocabulary (`config.py`), which a real project would supply from its piping class / catalog.
  **This makes the rules look stronger than they would be on real drawings.**
- No hand-drawn markups, revision clouds, stamps, multi-sheet continuations, weld numbers, or cut lengths.
- Labels avoid overlapping pipe geometry (good drafting practice); real drawings are messier.
- Scanned degradation is simulated, not from real scanners.
